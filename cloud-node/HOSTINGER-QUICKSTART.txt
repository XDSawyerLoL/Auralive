AURA Cloud Node — Hostinger 2.2.1 — CANONICAL / ZERO COST

SOURCE À DÉPLOYER
- Dépôt : XDSawyerLoL/Auralive
- Runtime canonique : cloud-node/
- Artefact GitHub Actions recommandé : aura-cloud-hostinger
- Ne pas déployer l'ancien paquet Python deploy/hostinger/.

RÉGLAGES HOSTINGER
- Framework : Other / Node.js
- Node.js : 22.x
- Répertoire racine du ZIP : ./
- package.json doit être directement à la racine
- server.js doit être directement à la racine
- Installation : npm install --omit=dev
- Démarrage : npm start
- Output directory : vide
- PORT : fourni par Hostinger et honoré automatiquement par server.js

ACCÈS DIRECT
- Le dashboard AURA est public.
- POST /api/chat fonctionne sans AURA_CLOUD_TOKEN, avec session navigateur signée et rate limiting.
- Aucun champ "Accès privé" ni token n'est demandé à l'utilisateur.
- AURA_CLOUD_TOKEN est optionnel et protège uniquement les endpoints privés d'administration / bridge.
- Ne jamais exposer AURA_CLOUD_TOKEN dans le navigateur.

GARANTIE FINANCIÈRE
- AURA_ZERO_COST_MODE=true doit rester activé.
- Aucun fallback Gemini/OpenAI distant potentiellement facturable.
- Expert Bridge externe bloqué en mode zéro coût.
- TTS Gemini Cloud bloqué.
- Mairaiy utilise Providence/Kokoro ff_siwis via la route Quantic autorisée à 0 €.
- Sans capacité gratuite disponible, AURA reste sur son noyau natif plutôt que de dépenser.

ARCHITECTURE DE DÉMARRAGE
- un seul process Node
- un seul listener Fastify public
- bind 0.0.0.0
- PORT Hostinger prioritaire
- MySQL démarre sans empêcher l'interface de répondre
- timeout connexion MySQL : 5 s par défaut

VÉRIFICATION APRÈS DÉPLOIEMENT
1. GET / doit afficher :
   AURA 2.2.1 · LONG HORIZON

2. GET /__aura_gateway doit retourner :
   "gateway_ready": true

3. GET /api/bootstrap/status doit retourner :
   "product": "AURA Cloud"
   "version": "2.2.1"
   "server_ready": true

4. GET /api/auth/session peut retourner authenticated:false :
   c'est normal en accès direct et cela ne doit pas bloquer le chat.

5. POST /api/chat doit répondre sans Authorization Bearer lorsque le runtime est prêt.

6. GET /api/voice/status doit indiquer Mairaiy / aura-voice-fabric lorsque le service voix est joignable.

DIAGNOSTIC D'UN ANCIEN DÉPLOIEMENT
- Si la page affiche "Accès privé", AURA_CLOUD_TOKEN à saisir, ou un badge antérieur à 2.2.1 :
  Hostinger sert encore un ancien paquet ou un ancien processus.
- Redéployer l'artefact aura-cloud-hostinger et redémarrer l'application.
