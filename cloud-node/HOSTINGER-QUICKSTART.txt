AURA Cloud Node 3.0 — Cerveau causal / homéostasie v10
GUIDE DE DÉPLOIEMENT ET DE RÉCUPÉRATION HOSTINGER

SOURCE CORRECTE
- Dépôt GitHub : XDSawyerLoL/Auralive
- Source canonique : cloud-node/
- Archive : aura-cloud-hostinger (artefact de la CI)
- NE PAS utiliser l'ancien paquet Python deploy/hostinger/.
- Dans le ZIP, package.json et server.js doivent être DIRECTEMENT à la racine.
- Le ZIP ne contient PAS les secrets MySQL nécessaires au démarrage.

INSTALLATION / MISE À JOUR
1. Dans Hostinger hPanel, ouvrir l'application Node.js AURA (ne pas créer une autre application).
2. Conserver les variables d'environnement, la base MySQL existante et les données.
   Ne pas supprimer les tables, ni remplacer un .env qui contient des secrets.
3. Remplacer les fichiers applicatifs à la racine par ceux du ZIP.
4. Node.js : 22.x ; installation : npm install --omit=dev ; commande : npm start.
5. Le serveur écoute sur 0.0.0.0. Il utilise AURA_PORT, sinon PORT fourni
   par Hostinger, sinon 3000. Éviter de forcer un port différent du port géré.
6. AURA_GATEWAY_ONLY doit être false ou absent. Si true, seule la passerelle
   HTTP démarre : le noyau et la mémoire restent indisponibles.
7. Redémarrer l'application Node.js depuis hPanel.

VARIABLES NÉCESSAIRES POUR LE NOYAU PERSISTANT
  NODE_ENV=production
  AURA_ZERO_COST_MODE=true
  AURA_GATEWAY_ONLY=false

  # Choisir l'une des deux méthodes MySQL :
  DATABASE_URL=mysql://...             (si Hostinger fournit une URL)
  # OU (si pas d'URL)
  DB_HOST=...
  DB_PORT=3306
  DB_USER=...
  DB_PASSWORD=...
  DB_NAME=...

  # Administration privée recommandée :
  AURA_CLOUD_TOKEN=<secret unique conservé uniquement côté serveur>

Ne PAS saisir les secrets dans la conversation ni dans l'URL du navigateur.
Les identifiants doivent être définis dans les variables d'environnement hPanel.
Le noyau ne peut pas fonctionner durablement sans base MySQL accessible.

DIAGNOSTIC VÉRIFIABLE
- Ouvrir /cerveau.
- Si le noyau est indisponible, un bandeau en haut affiche désormais :
  code public d'incident, état MySQL, dernière tentative, et consigne.
- Le code public est calculé sans exposer le serveur MySQL ni les mots de passe.
- GET /api/brain/graph -> runtime_diagnostic indique la catégorie exacte
  connue par le processus et les compteurs de traces réellement disponibles.
- GET /healthz -> ready:true avec db:true confirme le noyau persistant ;
  ne pas confondre HTTP 200, gateway_ready et runtime_ready.
- GET /__aura_gateway -> application_ready:true confirme seulement Fastify.
- GET /api/build -> identité de version et état du déploiement.

CODES D'INCIDENT / ACTIONS
- database-unconfigured : renseigner DATABASE_URL ou DB_HOST/USER/PASSWORD/NAME.
- database-authentication : vérifier l'utilisateur et le mot de passe MySQL.
- database-missing : vérifier le nom et l'existence de la base MySQL.
- database-dns : vérifier l'adresse de l'hôte MySQL.
- database-timeout / database-connection : vérifier l'accès réseau / les quotas.
- database-schema : vérifier migrations et permissions SQL, sans supprimer les données.
- gateway-only : désactiver AURA_GATEWAY_ONLY puis redémarrer Node.js.
- kernel-failed : lire les journaux de l'application dans hPanel.
- memory-exhausted : vérifier la limite mémoire Node / réchauffement du LLM.
- starting : attendre la prochaine observation de démarrage.

Le serveur réessaie automatiquement toutes les 15 secondes lorsque MySQL est
configuré. Le bouton « Relancer (administrateur) » n'est visible qu'avec une
session AURA privée et n'écrase aucune donnée. Corriger l'environnement en
premier si MySQL est absent : une relance ne peut pas créer les identifiants.

INTERFACE UNIQUE
- / et /cerveau servent la même interface.
- Le chat public borné ne nécessite pas le jeton administrateur.
- Les missions privilégiées et relances manuelles restent protégées.
- La carte affiche les modules du code séparément des transitions brain-hop.
- Une requête enregistrée corrèle son trajet, sa décision et les variations
  homéostatiques ; pas de fausse animation d'outil.
- En cas d'absence de base de traces, les compteurs affichent « — »,
  et non « 0 » prétendant qu'il n'y a eu aucune activité.
- Les indices émotionnels sont des états logiciels, pas des émotions humaines.

CONFIRMATION
1. Après redémarrage, vérifier /healthz -> ready:true, db:true.
2. Ouvrir /cerveau et vérifier le badge « Noyau joignable ».
3. Envoyer une question simple ; vérifier la réponse et son identifiant de trajet.
4. Vérifier la dernière mutation et, lorsque disponible, la corrélation
   « Signal → décision → état ».
5. Vérifier le retour au repos après une action échouée et sa preuve de trace.
6. Ne pas conclure « réparé en production » si une de ces preuves manque.

COÛTS
Aucun VPS, service payant supplémentaire ou fournisseur IA obligatoire.
Le mode AURA_ZERO_COST_MODE=true reste recommandé. Un fournisseur distant
ne doit être activé que si son plan gratuit est confirmé dans sa configuration.
